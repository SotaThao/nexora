Customer Tips API Mock Data Removal - Test Plan and QA Report

Date: 2026-06-07

Scope: remove customer tips mock-data dependency from the production customer flow, align with local API docs, Swagger, and OpenSpec, and verify the Merchant/Public Business endpoint dependency where businessId is required.

Not ready for release

Executive Status

The API integration structure exists, but QA found P0 gaps that can still create duplicate tips, hide valid payment methods, or keep production API mode partially dependent on simulation/local mock behavior.

Validated: OpenSpec strict validation passes. Existing merchant/dashboard repository tests pass. Public touch and public business repository/hook modules exist.

  • P0: WalletDetails confirms by calling handlePay(...), which can create a second tip in API mode.
  • P0: GET /public/touch/{businessSlug}/{touchPointSlug}/payment-link exists but is not wired into the payment flow.
  • P0: Single-staff payment buttons still rely on staff.paymentAccounts instead of API availablePaymentMethods.
  • P0: Business payment mapping reads handle/address/value, but Swagger DTO uses accountInfo.
  • P1: Existing tests still assert old mock/demo contracts and fail against the API contract.

API Contract Notes

  • Customer touch flow should obtain businessId from touchPageData.business.id.
  • Do not derive businessId from client mock merchant setup, local profile state, or route slugs.
  • Public business methods must be disabled until a real businessId is available.
  • Single-staff methods should come from StaffForTipDto.availablePaymentMethods.
  • Business-level method display should use PublicPaymentMethodDto.accountInfo.

Findings

P0 - Duplicate Tip Risk in Wallet Confirmation

src/components/customer-flow/steps/WalletDetails.jsx does not accept or call handleConfirmTip. In API mode, confirmation must call the confirm mutation, not create-tip again.

P0 - Payment Link Endpoint Is Not Used

src/components/customer-flow/hooks/useCustomerFlow.js has repository support for getPaymentLink, but handlePay moves to wallet details immediately after creating a tip.

P0 - API Staff Payment Methods Can Be Hidden

Payment.jsx filters single-staff payment buttons through staff.paymentAccounts. API mode should use availablePaymentMethods.

P0 - Business Payment Account Mapping Uses Wrong Fields

Business payment methods should map accountInfo first. Current mapping uses handle || address || value.
