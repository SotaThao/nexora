# docs/

This folder holds product/spec documentation and historical artifacts — it is distinct from the root-level "rule" docs and the design system:

- [`AGENTS.md`](../AGENTS.md) — engineering rules for any AI coding agent working in this repo.
- [`CLAUDE.md`](../CLAUDE.md) — pointer to `AGENTS.md` (exists only because Claude Code looks for this filename).
- [`CULTURE.md`](../CULTURE.md) — the US product-culture rule.
- [`ARCHITECTURE.md`](../ARCHITECTURE.md) — the codebase's structural map (folders, data boundary, domain modules).
- [`DESIGN.md`](../DESIGN.md) — the visual design system (tokens, components).
- [`README.md`](../README.md) — test/lint automation guide.

## What's here

- **`standard/`** — dedicated design/engineering standard docs split out of `AGENTS.md` because they're specific to one module, not a rule every agent needs for every task. Currently: `pos-ipad-design-standard.md` (the POS module's iPad-specific layout conventions — radius scale, touch targets, spacing, font scale, interaction patterns — and its tracked redesign backlog).
- **`uiux-feedback/`** — dated, living-doc UI/UX review feedback for specific screens, meant to be actioned by an AI agent (currently: nail salon booking, POS order list/detail).
- **`archive/2026-05-26-product-spec-snapshot/`** — a point-in-time dump of product/spec/API/test-case documents from 2026-05-26 (largely duplicated as `.md` + `.docx` pairs, plus a test-case `.xlsx` and two standalone HTML mockups). Treat this as historical reference, not a live source of truth — for current API contract, see `AGENTS.md`'s "Contract from live Swagger" section; for current product specs, check `user-story/` and `openspec/`.
- **`superpowers/`** — plans/specs generated by the `superpowers` skill workflow during past sessions (`plans/`, `specs/`).

Not covered by this folder: `openspec/` (change proposals + specs), `user-story/` (integration goal stories), and `API/` (API contract snapshots) all remain their own top-level folders — see `AGENTS.md`'s File Map.
